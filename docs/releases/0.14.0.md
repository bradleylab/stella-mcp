# Stella MCP 0.14.0

Status: locally verified release candidate; no tag, publication, or release has been performed

This is the cumulative successor to public 0.12.0. It includes the
compatibility and evaluation hardening developed under the unpublished 0.13.0
internal candidate, then moves Stella onto the stable MCP Python SDK v2 line
and the vendor-neutral MCP 2026-07-28 protocol while retaining the existing
scientific, XMILE, simulation, and evaluation behavior.

## Compatibility and Evidence Hardening Since 0.12.0

- Vendor a pinned and attributed subset of the MIT-licensed SDXorg test-models
  corpus and classify arrays, compositional module instances, and additional
  top-level models before conversion. Unsupported constructs are rejected in
  strict workflows and preserved with warnings where practical in permissive
  round-trips.
- Add supported-semantic signatures, separate UUID metadata signatures, stable
  JSON Pointer differences, and synchronized capability reports for retained
  external, package, desktop, and simulation fixtures.
- Upgrade numeric comparison to schema v2 with exact or explicitly declared
  rounded-reference-label alignment, no interpolation, finite/grid validation,
  backend metadata, raw discrepancies, and no scientific pass threshold.
- Retain Stella Professional 4.1.1 open, run, export, save, strict re-import,
  layout, and numeric evidence for the five built-in templates and a scalar
  graphical-function case.
- Reject confirmed Stella/XMILE reserved identifiers in strict mode and rename
  the bundled SIR parameters to `transmission_rate` and `recovery_rate` without
  changing their values or the model's mathematics.
- Use agent evaluation protocol v2 with three fresh runs per scenario and
  separate workflow, semantic, artifact, completion, and tool-health outcomes.

The retained numeric record includes every non-zero discrepancy. In particular,
the Lotka-Volterra `predation` difference remains documented as a Stella/PySD
backend-semantic limitation and is not accepted through a tolerance.

## Highlights

- Serve MCP 2026-07-28 and supported legacy clients from one stdio artifact.
- Replace protocol-session identity with explicit isolated application
  workspaces. Modern stateful calls carry an opaque `workspace_id`; legacy
  stdio calls may use one documented process-local compatibility workspace.
- Append `create_workspace` and `revoke_workspace` after the existing 42 tools.
- Add structured success payloads to the 17 formerly text-only tools and JSON
  Schema 2020-12 output contracts to all 44 tools while retaining readable text.
- Route modern model resources through
  `stella://workspaces/{workspace_id}/models/{model_id}` without ambient request
  context. Legacy stdio retains `stella://models/{model_id}`.
- Preserve classified tool errors; successful results are schema-validated,
  while error envelopes remain a separate contract as required by SDK behavior.
  Unexpected internal failures use a generic message rather than exposing
  exception details.

## Compatibility Boundary

The same installed server is tested with the SDK v2 client in modern and
legacy modes. Existing tool names, their original order, annotations, text
outcomes, structured field meanings, and Stella/XMILE behavior remain intact.
Modern discovery marks `workspace_id` required for stateful tools, and modern
clients must create and supply one for those calls. Legacy discovery retains
the optional field and process-local fallback. Optional MCP extensions are not
required for this migration.

This release ships stdio only. Workspace identifiers are routing handles, not
authorization credentials; a future multi-user HTTP deployment must bind them
to independently authenticated principals.

## Deliberate Exclusions

Code Mode, `StellaAPI`, model-generated code execution, and the optional Tasks
extension are not part of 0.14.0. Code Mode evaluation begins only after the
published artifacts pass post-publication verification and the sanitized
release evidence is durably merged.

## Installation After Release

`0.14.0` is not an installation target until publication completes.

```bash
pip install "stella-mcp==0.14.0"
```

Optional simulation support remains:

```bash
pip install "stella-mcp[sim]==0.14.0"
```

Local verification evidence is recorded in
`docs/evaluation/0.14.0-release-gates.md`. Publication, tag, main-branch CI,
and post-publication client checks remain separate release actions.
