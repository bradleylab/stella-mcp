# Stella MCP 0.13.0

Status: release candidate; Trust the Loop hardening milestone complete

This release makes compatibility and evaluation boundaries explicit. It adds
pinned external fixtures, early unsupported-feature failures, semantic and
numeric fidelity records, Stella identifier safety, repeated agent evidence,
and broader Stella Professional acceptance for the features already shipped.

## Highlights

- Vendor a pinned, attributed subset of the MIT-licensed SDXorg test-models
  corpus. Supported SIR and teacup cases strict-import and simulate; array and
  nested-module controls are classified as preserved-only.
- Detect arrays, compositional module instances, and additional top-level
  models before conversion. Strict import/export rejects every detected code;
  permissive workflows warn and preserve the selected XML structures where
  practical; every PySD-backed path rejects them before compilation.
- Add reusable supported-semantic signatures, UUID metadata signatures, and
  stable JSON Pointer differences for round-trip and targeted-edit checks.
- Reject confirmed Stella/XMILE reserved identifiers in strict mode. The
  bundled SIR template now uses `transmission_rate` and `recovery_rate` instead
  of `beta` and `gamma`, retaining the same parameter values and mathematics.
- Upgrade numeric comparison to schema v2 with exact or explicitly declared
  rounded-reference-label alignment, no interpolation, finite/grid checks,
  engine and artifact metadata, and no scientific pass threshold.
- Retain Stella Professional 4.1.1 open/run/export/save/strict-reimport evidence
  for all five built-in templates and a scalar graphical-function model. Stella
  preserved every identifier and effective computational signature.
- Regenerate four built-in layouts into compact one-page diagrams. All built-ins
  passed the automated layout gates and desktop visual review without stock
  overlap or connector crossing.
- Upgrade agent protocol v2 to three fresh runs per scenario with separate
  workflow, semantic, artifact, completion, and tool-health outcomes. All 9
  retained personal OpenAI runs passed every required dimension across 51 MCP
  calls with no failed, recovered, or errored tool outcome. This is a raw count,
  not a population success estimate.
- Generate synchronized capability and numeric-fidelity JSON/Markdown evidence,
  scoped explicitly to the retained fixtures.

## Compatibility Boundary

Arrays, nested models, and compositional module instances are not implemented
in 0.13. Permissive preservation is intended for inspection and round-tripping;
editing supported variables does not guarantee references inside preserved-only
fragments are updated. Strict mode is the final compatibility gate.

PySD remains optional and uses Euler integration. Every simulation result now
reports the backend version, actual and model-declared methods, feature
preflight, and warnings.

## Numeric Review

The retained accumulator and carbon-cycle cases match exactly. Other scalar
cases mostly differ at the precision retained in Stella CSV output. The
Lotka-Volterra `predation` flow differs materially at time 41: Stella caps the
outflow to keep the non-negative `Prey` stock from crossing below zero, while
PySD reports the uncapped flow equation even though both trajectories reach
zero prey at the next model time. This is a documented backend-semantic
limitation, not a tolerated parity result.

The complete raw review is in
`docs/evaluation/0.13.0-numeric-fidelity.md`; the fixture-by-fixture scope is in
`docs/evaluation/0.13.0-capability-matrix.md`; completed local release gates are
recorded in `docs/evaluation/0.13.0-release-gates.md`.

The core install continues to require only MCP. Install optional simulation
support with:

```bash
pip install "stella-mcp[sim]==0.13.0"
```
