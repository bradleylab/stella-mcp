# Stella MCP 0.12.0

This release adds reproducible evidence for the package's MCP, Stella desktop,
simulation, and free-form tool-use workflows. It also corrects the built-in SIR
diagram found during desktop evaluation.

## Highlights

- Add deterministic end-to-end scenarios that launch Stella MCP through a real
  stdio client and exercise construction, strict round-trips, error recovery,
  simulation, scenario comparison, sensitivity analysis, and calibration.
- Add Stella Professional 4.1.1-saved compatibility fixtures with provenance,
  strict parsing, semantic round-trip checks, and desktop screenshots.
- Compact the built-in SIR diagram into one visible page. Stella Professional
  4.1.1 opened, ran, and saved the corrected model without repair.
- Record a no-interpolation numeric comparison in which Stella Professional
  4.1.1 and PySD 3.14.3 produced identical accumulator, input, and rate values
  at every saved time point in the linear accumulator fixture.
- Add a separately documented free-form tool-use harness and one retained
  personal OpenAI sample. It completed all three scenarios with 17 successful
  MCP calls, no tool errors, and all five expected artifacts; two scenarios
  passed every preregistered criterion.
- Raise the tested MCP SDK floor to 1.19.0 and exercise that minimum explicitly
  in CI.
- Refresh the repository lockfile to patched MCP and web-stack dependencies;
  the resulting versions fall outside all 16 Dependabot advisory ranges that
  were open before the refresh.

The free-form result is one sample, not an estimated success rate. Its growth
scenario completed the requested workflow but failed the exact protocol check
because it used `Year` where the protocol required `Years`; the retained result
was not rescored.

The core install continues to require only MCP. Simulation, scenario analysis,
sensitivity analysis, and calibration remain available through the optional
`sim` extra:

```bash
pip install "stella-mcp[sim]==0.12.0"
```

The deterministic and free-form evaluation code is maintained in the source
repository and is not added to the wheel's runtime dependency surface.
