# Stella MCP 0.12.0

Status: release candidate; layout-quality milestone complete

This release adds a deterministic directed layout pipeline and reproducible
evidence for the package's MCP, Stella desktop, simulation, and free-form
tool-use workflows.

## Highlights

- Replace best-effort force placement with a staged directed layout pipeline:
  strongly connected component placement, deterministic component packing,
  distinct stock ports, orthogonal flow routing, obstacle-aware connector
  routing, target-aware auxiliary placement, label-side selection, and dynamic
  page grids.
- Preserve locked paths before routing unlocked flows and connectors, size label
  obstacles from imported view fonts, and select label sides in deterministic
  normalized-name order.
- Return structured layout metrics and stable `layout.*` warnings from
  `save_model`, `get_model_xml`, and `render_diagram`. Every planar benchmark
  and built-in template passes the overlap, crossing, route, page, lock, and
  repeatability gates; the known non-planar control reports one deterministic
  `layout.unavoidable_crossing` warning.
- Prefer direct information connectors when unobstructed and unshared, retain
  Stella-compatible orthogonal stock-flow routes, and report any avoidable
  route detour as a release-gate failure.
- Treat coordinates supplied by stock, flow, or auxiliary update operations as
  user-authored geometry so later automatic layouts preserve those edits.
- Add retained Stella Professional 4.1.1 source/save/screenshot evidence for
  SIR, Lotka-Volterra, chain, eight-way fan-out, and six-stock feedback. All
  five opened, ran, saved, and strict-imported with exact supported semantics,
  element centers, page grids, labels, and flow routes.
- Add deterministic end-to-end scenarios that launch Stella MCP through a real
  stdio client and exercise construction, strict round-trips, error recovery,
  simulation, scenario comparison, sensitivity analysis, and calibration.
- Add Stella Professional 4.1.1-saved compatibility fixtures with provenance,
  strict parsing, semantic round-trip checks, and desktop screenshots.
- Compact the built-in SIR diagram into one visible page.
- Record a no-interpolation numeric comparison in which Stella Professional
  4.1.1 and PySD 3.14.3 produced identical accumulator, input, and rate values
  at every saved time point in the linear accumulator fixture.
- Add a separately documented free-form tool-use harness and one retained
  personal OpenAI sample. It completed all three scenarios with 17 successful
  MCP calls, no tool errors, and all five expected artifacts; two scenarios
  passed every preregistered criterion.
- Raise the tested MCP SDK floor to 1.19.0 and exercise that minimum explicitly
  in CI.
- Refresh the repository lockfile to patched MCP and web-stack dependencies;
  the resulting versions fall outside all 16 Dependabot advisory ranges that
  were open before the refresh.

The free-form result is one sample, not an estimated success rate. Its growth
scenario completed the requested workflow but failed the exact protocol check
because it used `Year` where the protocol required `Years`; the retained result
was not rescored.

The core install continues to require only MCP. Simulation, scenario analysis,
sensitivity analysis, and calibration remain available through the optional
`sim` extra:

```bash
pip install "stella-mcp[sim]==0.12.0"
```

The deterministic and free-form evaluation code is maintained in the source
repository and is not added to the wheel's runtime dependency surface.
