# Stella MCP 0.11.0 Evaluation Baseline

## Confirmed

- The real stdio lifecycle initializes the `stella-mcp` server and discovers 42
  tools, one prompt, template resources, and session-model resources.
- All five deterministic scenarios passed with the simulation capability: 19
  MCP tool calls, zero failed scenarios, and zero skipped scenarios.
- The scenarios cover construction, validation, rendering, strict save/import,
  structured error recovery, simulation, scenario comparison, sensitivity
  analysis, and calibration.
- Three generated models opened without repair in Stella Professional 4.1.1,
  ran to their configured final times, and were saved by Stella.
- The Stella-saved growth, SIR, and accumulator files strict-import with zero
  compatibility warnings and preserve supported semantics after another
  export/reparse cycle.
- Native stdio testing established MCP 1.19.0 as the dependency floor: the same
  lifecycle fails under 1.18.0 and passes under 1.19.0.

The machine-readable run is recorded in
`results/evaluation/0.11.0-baseline.json`; its Markdown rendering is adjacent.
The registered desktop files and provenance are in
`tests/fixtures/compat_corpus/manifest.json`.

## Finding

Growth and accumulator diagrams were visually usable. The SIR diagram was not:
one information connector left the visible canvas and another crossed most of
the view. This is a layout-quality defect, not an XMILE import or simulation
failure. The desktop screenshot is in
`docs/evaluation/images/stella-4.1.1-sir.jpg`.

## Evidence Gap

Desktop numeric parity with Stella was not established. Stella Professional
4.1.1 created the requested export path during the automated desktop attempt,
then exited before writing values; the resulting temporary CSV was empty. No
numeric result or tolerance is claimed. `evaluation.compare_runs` is ready to
compare a future non-empty Stella export against the PySD CSV without
interpolation or an assumed pass threshold.

The deterministic suite also does not measure free-form LLM planning quality.
That requires a separately approved endpoint and a fixed agent-evaluation
protocol.
