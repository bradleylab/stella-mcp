# Stella MCP 0.9.0 — Scenario Comparison & Sensitivity Analysis

**Goal:** Turn the existing single-run `simulate` tool into a small analysis suite. Let an agent ask the two questions a modeler asks immediately after a model runs: *"what happens under these alternative assumptions?"* (`compare_scenarios`) and *"which parameters actually move the outcome, and how much?"* (`sensitivity_analysis`).

**Architecture:** Both tools are *compositions of the existing engine*. `run_simulation` already (a) runs on a `copy.deepcopy` so the session model is never mutated, (b) resolves/validates override names against model variables, and (c) returns downsampled, NaN-aware series. The new work chooses **which override sets to run** and **how to reduce the results** — no new runtime dependency. New code lives in a focused `stella_mcp/analysis.py`; `simulate.py` is refactored only to compile the PySD model once so a sweep does not recompile per run.

**Prerequisite:** 0.8.0 shipped (this plan assumes `simulate`, the `sim` extra, tool annotations, the `_READ_ONLY/_IDEMPOTENT/_MUTATING/_DESTRUCTIVE` annotation sets + partition test, and lockfile-based CI exist).

**Scope guard:**
- **Sensitivity = OAT (one-at-a-time) only.** `mode` is an enum with the single value `"oat"`; `"grid"` and `"montecarlo"` are reserved (widening the enum later is non-breaking). No factorial/Monte-Carlo sampling, no Sobol indices.
- **No calibration in this release.** Fitting parameters to data (the scipy-dependent tool) is the next arc; nothing here adds a numerical-optimization dependency or reads observational data.
- No new charting/rendering — results are structured data + optional CSV, not plots.
- Tools are read-only against the session model (they run on copies); the only side effect is an optional CSV write, which mirrors `simulate`'s `save_results_csv`.

### Task 1: Compile-once runner (behavior-preserving refactor of `simulate.py`)

**Files:** Modify `stella_mcp/simulate.py`; `tests/test_simulate.py` stays green unchanged.

**Why:** `run_simulation` currently writes a temp `.stmx` and calls `pysd.read_xmile(...)` on *every* call. A sensitivity sweep is up to `max_runs` simulations of the *same* model with different `params`; recompiling the XMILE each time would dominate wall-clock (PySD's `read_xmile` is the expensive step; `.run()` is cheap). Factor the compile step out so the sweep compiles once and loops `.run(params=...)`.

- [ ] **Step 1 — Verify the PySD contract first (grounding).** Before refactoring, confirm in a scratch session that a single compiled PySD model is **stateless across repeated `.run(params=...)` calls** — i.e. `runner.run(params={'k': 1})` then `runner.run(params={'k': 2})` gives the same second result as compiling fresh. If PySD carries state between runs, the analysis tools must recompile per run (fall back to calling `run_simulation` per run) — record which is true in the module docstring. Do not assume; the whole refactor rests on this.

- [ ] **Step 2 — Extract `_compile_runner`.** Introduce an internal helper that does the deepcopy → temp-file → `read_xmile` → cleanup dance once and returns the compiled runner plus the name-resolution closures (`resolve`, `all_keys`) that `run_simulation` already builds. `run_simulation` is rewritten to call it, then run once. Keep the temp-file cleanup in a `finally` exactly as today. **The public signature and return shape of `run_simulation` do not change** — this is a pure refactor; `tests/test_simulate.py` is the regression gate and must pass untouched.

- [ ] **Step 3 — Expose a reusable single-run reducer.** Pull the "DataFrame column → downsampled points + summary" logic into a helper `summarize_run(results, report_keys, model, max_points)` so both `simulate` and `analysis.py` produce identical series structures. Again behavior-preserving.

- [ ] **Step 4 — Verify, commit.**
```bash
uv run --extra dev --extra sim python -m pytest tests/test_simulate.py -v   # unchanged, green
git commit -m "refactor: compile the PySD runner once for reuse across runs"
```

### Task 2: `compare_scenarios` (what-if)

**Files:** Create part of `stella_mcp/analysis.py`, `tests/test_analysis.py`; modify `tool_schemas.py`, `tool_handlers.py`, `README.md`.

**What it answers:** run several named alternative-assumption sets side by side and report how each diverges from a baseline.

**Tool schema (`compare_scenarios`):**
```jsonc
{
  "model_id": "<optional; current model if omitted>",
  "scenarios": [                                  // required, ≥1
    {"name": "high_emissions", "overrides": {"emission_rate": 12}}
  ],
  "baseline": {"emission_rate": 8},               // optional; default = the unmodified model
  "include": ["Atmosphere", "Ocean"],             // optional; default = all stocks
  "max_points": 101,                              // per-series cap (first/last always kept)
  "save_comparison_csv": "<optional path>"        // wide table: time × (variable, scenario)
}
```

**Result (structured):**
```jsonc
{
  "model_id": "...",
  "sim_specs": { "...": "..." },
  "baseline": { "overrides": {...}, "series": [ {name, points, summary} ], "warnings": [...] },
  "scenarios": [
    { "name": "high_emissions", "overrides": {...},
      "series": [ {name, points, summary} ],
      "delta_vs_baseline": { "Atmosphere": {"final_abs": +37.2, "final_pct": +18.4,
                                            "max_abs": +37.2} },
      "warnings": [...] }
  ]
}
```

**Implementation notes:**
- **Fail-fast / atomic validation.** Resolve *every* override name in `baseline` and all `scenarios` against model variables **before running anything** (reuse `run_simulation`'s `resolve`). A typo in scenario 3 must error naming `(scenario "x", variable "y")` with the valid-name list, not after two scenarios already ran.
- **Baseline default** is the unmodified model (overrides `{}`). A caller can pass an explicit `baseline` override set; deltas are always against whatever baseline resolves to.
- **Deltas** computed only on the per-variable `summary` (final/max), and only for variables present in both runs; `final_pct` is `None` when the baseline final is 0 (no divide-by-zero — report absolute only and note it).
- **Per-scenario failures are warnings, not exceptions.** A scenario whose run produces NaN/inf surfaces `run_simulation`'s non-finite warning in *that scenario's* `warnings`; it does not abort the others.
- **Duplicate scenario names** → hard error (the name is the join key for the comparison).
- Runs on copies via the shared runner; the session model is untouched.

- [ ] **Step 1 — Failing tests** (`tests/test_analysis.py`, skipped without pysd, mirroring `test_simulate.py`):
  - Two scenarios on a known 1-stock/1-flow model produce different finals; `delta_vs_baseline` signs/magnitudes are correct against a hand-computed baseline.
  - Override typo in one scenario raises before any run, message names the scenario and the bad variable.
  - Duplicate scenario names raise.
  - Baseline defaults to the unmodified model when omitted (delta of an identical scenario is ~0).
  - `final_pct` is `None` (not a crash) when baseline final is 0.
  - Empty `scenarios` raises.
- [ ] **Step 2 — Implement `compare_scenarios(...)`** in `analysis.py` using the shared runner (compile once; one `.run()` per scenario+baseline).
- [ ] **Step 3 — Tool schema + handler.** `register("compare_scenarios")`; response = text summary (per-scenario final deltas) + structured payload. Add `compare_scenarios` to **`_IDEMPOTENT_TOOLS`** (optional CSV write, no model mutation) so the partition test passes.
- [ ] **Step 4 — README** "Scenario Comparison" subsection with an example call. Verify, commit.
```bash
uv run --extra dev --extra sim python -m pytest tests/test_analysis.py -v
git commit -m "feat: add compare_scenarios what-if tool"
```

### Task 3: `sensitivity_analysis` (OAT)

**Files:** Extend `stella_mcp/analysis.py`, `tests/test_analysis.py`; modify `tool_schemas.py`, `tool_handlers.py`, `README.md`.

**What it answers:** sweep one parameter at a time across a range, holding the others at baseline, and report how a single chosen output metric responds — plus a normalized sensitivity so knobs can be ranked.

**Tool schema (`sensitivity_analysis`):**
```jsonc
{
  "model_id": "<optional>",
  "parameters": [                                  // required, ≥1; each is one of:
    {"name": "emission_rate", "start": 5, "stop": 15, "steps": 6},   // even grid
    {"name": "uptake_fraction", "values": [0.1, 0.2, 0.4]}           // explicit points
  ],
  "output": {                                      // required
    "variable": "Atmosphere",
    "metric": "final",                             // final | max | min | mean | time_to_threshold
    "threshold": 600                               // required iff metric == time_to_threshold
  },
  "mode": "oat",                                   // enum ["oat"]; grid/montecarlo reserved
  "max_runs": 200,                                 // hard guard (excludes the 1 baseline run)
  "include_series": false,                         // also return each run's downsampled series?
  "save_sweep_csv": "<optional path>"              // long table: parameter, value, metric
}
```

**Result (structured):**
```jsonc
{
  "model_id": "...",
  "output": {"variable": "Atmosphere", "metric": "final"},
  "baseline": {"overrides": {}, "metric_value": 410.0},
  "parameters": [
    { "name": "emission_rate",
      "points": [ {"value": 5, "metric": 380.1}, {"value": 15, "metric": 612.4} ],
      "range_sensitivity": 23.2,        // (metric_hi − metric_lo)/(value_hi − value_lo)
      "elasticity": 1.7,                // normalized at baseline: (Δmetric/metric0)/(Δp/p0), null if undefined
      "warnings": [] }
  ],
  "total_runs": 12,
  "warnings": []
}
```

**Implementation notes:**
- **OAT semantics:** for each parameter, vary it across its grid while *all other parameters stay at their model-defined baseline* (no override). One baseline run (no overrides) is computed once for `elasticity` and reporting.
- **Metric reducer** `_reduce_metric(times, values, metric, threshold)`:
  - `final` = last value; `max`/`min`/`mean` over **finite** values only (reuse the `math.isfinite` discipline already in `simulate.py`);
  - `time_to_threshold` = the first `t` where the series **crosses** `threshold` (first index with `value >= threshold` when it starts below, or `value <= threshold` when it starts above); `None` + warning if it never crosses. Document the crossing convention in the docstring; do not guess a direction silently.
  - Any non-finite metric → `None` for that point + a warning naming the parameter/value; never silently dropped.
- **Run-count guard:** `total = sum(steps_i)`; if `total > max_runs`, **raise** with the count and guidance ("reduce steps or raise max_runs") — OAT is a sum, so this only trips on genuinely large sweeps. Log the cap in the result, never silently truncate.
- **Grid input validation:** `steps >= 2` and `start != stop`; `values` needs `≥2` entries. Reuse `run_simulation`'s name resolution for `parameters[].name` and `output.variable`; `output.variable` is passed as the sole `include` so only it is simulated/returned.
- **`elasticity`** is `None` when `metric0 == 0` or `p0 == 0` (no divide-by-zero); `range_sensitivity` is reported regardless.
- Compile once via the shared runner; loop `.run(params={name: value})`.

- [ ] **Step 1 — Failing tests:**
  - Linear-ish model where the analytic slope is known: `range_sensitivity` matches within tolerance; `final` metric monotonic across the sweep.
  - `max`/`min`/`mean` reducers correct on a hand-built series (including a NaN point → finite-only summary + warning).
  - `time_to_threshold` returns the right crossing time, and `None`+warning when never crossed; missing `threshold` for that metric raises.
  - `max_runs` guard raises when `sum(steps) > max_runs`.
  - `steps < 2`, `start == stop`, and a 1-element `values` list each raise.
  - `elasticity` is `None` (not a crash) when baseline metric is 0.
- [ ] **Step 2 — Implement `sensitivity_analysis(...)`** in `analysis.py`.
- [ ] **Step 3 — Tool schema + handler.** `register("sensitivity_analysis")`; `mode` enum `["oat"]`. Add to **`_IDEMPOTENT_TOOLS`**. Response = text summary (ranked by `|elasticity|`) + structured payload.

## Self-Review

- **Spec coverage:** the two no-new-dep tools from the agreed 0.9.0 scope (what-if + OAT sensitivity); calibration explicitly deferred.
- **Dependency discipline:** zero new runtime dependencies. Both tools sit behind the existing `sim` extra purely because they call `run_simulation` (which imports pysd) — the `analysis.py` module guards nothing itself, inheriting `SimulationDependencyError` from the shared runner.
- **Engine reuse:** both tools are compositions of `run_simulation`; the only refactor compiles the PySD model once, and it is behavior-preserving with `tests/test_simulate.py` as the regression gate. The PySD statelessness assumption is *verified*, not assumed (Task 1 Step 1).
- **Method honesty (coding cardinal #3):** OAT is the only sensitivity method shipped, named as such; `mode` is a forward-compatible enum, not a silent default that could later change semantics. The `time_to_threshold` crossing convention and the finite-only metric reduction are documented, not implicit.
- **Failure discipline:** override typos fail fast and atomically; per-scenario / per-sweep-point blowups are surfaced as warnings naming the offender, never silently dropped; run-count caps raise with guidance rather than truncating.
- **No-crash math:** every ratio (`final_pct`, `elasticity`) guards its zero denominator and returns `None` with a note.
- **Statefulness:** tools never mutate the session model (run on copies); the only side effect is the opt-in CSV, consistent with `simulate`'s `save_results_csv`. Annotated `idempotentHint=True`, partition test updated.
