# Stella MCP 0.7.0 — Simulation, Batch Build, Parser Robustness

**Goal:** Close the build→verify loop (agents can run the models they build), cut the tool-call count for model construction by an order of magnitude, and make equation parsing correct for real-world imported models.

**Architecture:** Simulation is delegated to PySD behind an optional extra (`stella-mcp[sim]`) so the core package stays zero-dependency-beyond-mcp. Batch construction composes the existing `add_*` model methods on a deep copy and swaps atomically. Parser fixes live entirely in `stella_mcp/equation_parser.py` with downstream behavior changes in `validator.py` only.

**Tech Stack:** Python 3.10+, MCP Python SDK, PySD (optional extra), pytest, ruff, uv.

**Scope guard:** No diagram rendering, no units checking, no MCP resources/prompts/annotations — those are 0.8.0 (see `2026-06-10-feat-0.8.0-visualization-mcp-surface-plan.md`). No XMILE array/dimension support (unscheduled).

### Task 1: Equation Parser — Complete Reserved Tokens + Quoted Identifiers

**Files:**
- Modify: `stella_mcp/equation_parser.py`
- Modify: `stella_mcp/validator.py`
- Modify: `tests/test_equation_parser.py`

**Problem 1 — incomplete builtin list.** A Stella builtin missing from `STELLA_RESERVED_TOKENS` is treated as a variable reference: `validate_model` reports a false `undefined_variable` error and `sync_connectors_from_equations` fabricates a connector to a non-existent variable.

**Problem 2 — quoted identifiers are invisible.** XMILE equations reference variables whose names contain spaces/specials as quoted identifiers (`"net growth rate" * Population`). The current parser strips ALL quoted spans as string literals (`_STRING_LITERAL_PATTERN.sub("", ...)`), so those references are invisible to validation and connector sync on imported models.

- [ ] **Step 1: Write failing tests**

Append to `tests/test_equation_parser.py`:

```python
def test_extended_builtins_are_not_variable_refs():
    eq = "SINWAVE(amplitude, period) + ARCTAN(x) + EXPRND(rate) + CLOCKTIME"
    refs = extract_variable_references(eq)
    assert refs == {"amplitude", "period", "x", "rate"}


def test_quoted_identifiers_extracted_as_refs():
    eq = '"net growth rate" * Population'
    refs = extract_variable_references(eq)
    assert refs == {"net growth rate", "Population"}


def test_quoted_identifier_with_function_call():
    eq = 'MAX("carrying capacity" - Population, 0)'
    assert "carrying capacity" in extract_variable_references(eq)
```

(Adjust the first test's tokens to whichever builtins Step 2 actually adds.)

- [ ] **Step 2: Expand `STELLA_RESERVED_TOKENS` from the spec — do not invent the list**

Compile the token list from two authoritative sources and cross-check each entry:

1. XMILE v1.0 spec, OASIS standard, §3.5 "Built-In Functions" (https://docs.oasis-open.org/xmile/xmile/v1.0/xmile-v1.0.html) — the normative function set.
2. The isee Stella builtin reference (https://www.iseesystems.com/resources/help/v3/ → "Builtins") — Stella-specific extensions beyond the spec.

Known-missing examples to expect (verify each against the sources before adding): `SINWAVE`, `COSWAVE`, `ARCCOS`, `ARCSIN`, `ARCTAN`, `SINH`, `COSH`, `TANH`, `CLOCKTIME`, `GAMMALN`, `LOGNORMAL`, `UNIFORM`, `TRIANGULAR`, `BINOMIAL`, `GEOMETRIC`, `POISSON` (already present), `MONTECARLO`, `CGROWTH`, `CDECAY`. Group the final list in the source by spec-vs-Stella-extension with a comment citing each source. Every token must appear in one of the two references — no plausible-looking additions.

- [ ] **Step 3: Extract quoted identifiers**

In `extract_variable_references`, instead of discarding quoted spans, capture them first:

```python
quoted_refs = {match[1:-1] for match in _STRING_LITERAL_PATTERN.findall(equation)}
equation = _STRING_LITERAL_PATTERN.sub("", equation)
```

Add non-empty quoted strings to the returned set (inner text, case preserved, surrounding quotes stripped). Callers already normalize names: `sync_connectors_from_equations` filters through `_has_variable`, so a quoted span that isn't a model variable is dropped there.

- [ ] **Step 4: Handle quoted refs in EVERY consumer of `extract_variable_references`, not just one check**

Quoted refs flow into all downstream consumers; each needs an explicit decision (review finding — the original draft only covered undefined-variable validation):

- `_check_undefined_variables` (`validator.py`): a quoted span that matches no variable might be a genuine string argument (e.g., a label), so a hard error would be wrong. Emit severity `warning`, category `unresolved_quoted_reference` instead. Implementation: have `equation_parser` expose the quoted subset (a second function `extract_quoted_references(equation)`) and check membership.
- `_check_missing_connections` (`validator.py`): quoted refs that DO resolve to a variable participate normally (a missing connector to `"net growth rate"` is just as real); unresolved quoted refs are excluded (already covered by the `ref in all_vars` guard — verify with a test).
- `_check_circular_dependencies` (`validator.py`): uses `refs & aux_names`, so unresolved quoted spans drop out naturally — add a test locking that in.
- `sync_connectors_from_equations` (`xmile.py`): already filters through `_has_variable`, so unresolved quoted spans are dropped — add a test that a resolvable quoted ref produces a connector and an unresolvable one does not.
- Existing test `tests/test_equation_parser.py` (the one asserting quoted spans are ignored) encodes the old behavior and must be updated *deliberately* as part of this task, not loosened in passing.

### Task 3: Batch Construction — `build_model` and `add_variables`

**Files:**
- Modify: `stella_mcp/tool_schemas.py`, `stella_mcp/tool_handlers.py`
- Create: `tests/test_batch_build.py`
- Modify: `README.md`

Building a 15-variable model currently takes ~20 sequential tool calls. One call should do it.

**Design:**

- `build_model`: `create_model` + populate, one call. Args: `name`, optional `model_id`, optional `sim_specs` (`{start, stop, dt, method, time_units}`), `stocks: []`, `flows: []`, `auxs: []`, optional `connectors: []`, optional `modules: []`, `sync_connectors` (default `true`), `validate` (default `true`).
- `add_variables`: same payload arrays applied to an *existing* model (no `name`/`sim_specs`).
- Item schemas mirror the existing single-add tools exactly — same field names, same `graphical_function` sub-schema, same constraints. Reuse `model_id_property` and `graphical_function_schema` from `tool_schemas.py`; do not fork the shapes.
- **Module items need an explicit combined shape** (review finding: module functionality is split across `create_module`, `set_module_view`, and `set_module_style`, so "mirror the single-add tool" is ambiguous for modules). Module item: `{name, members, view?: {x, y, width, height}, style?: {border_color, background, font_color, font_size, label_side}}` — field names and constraints taken verbatim from the `set_module_view`/`set_module_style` schemas. `view`/`style` omitted → same defaults as `create_module` alone.
- **Application order:** stocks → auxs → flows → connectors → modules → connector sync. (Auxs before flows so flow equations referencing parameters validate cleanly; flows last among variables because they reference stocks.)
- **Atomicity:** all-or-nothing. Build into a scratch model (`build_model`: fresh `StellaModel`; `add_variables`: `copy.deepcopy` of the target), apply items, and only register/swap on full success. On failure return one structured error identifying the failing item: `{"error": {..., "stage": "flows", "index": 2, "item_name": "loss"}}`. Partial application is the failure mode this design exists to prevent — an agent retrying a half-applied batch creates duplicates.
- **Response:** structured `{"model_id", "added": {"stocks": n, "flows": n, "auxs": n, "connectors": n, "modules": n}, "connector_sync": {...}, "validation": {...}}` — reuse `model_to_summary` counts and the existing validation payload shape so agents get build+inspect+validate in one round trip.

- [ ] **Step 1: Write failing tests** in `tests/test_batch_build.py`: happy path (SIR-sized model in one call, assert counts and validation passed), atomic failure (3rd flow references duplicate name → error names stage/index AND model absent from session / target model unchanged), `add_variables` on existing model, `sync_connectors=false` respected, `graphical_function` accepted inside an aux item.

- [ ] **Step 2: Schemas.** Define `stock_item_schema` / `flow_item_schema` / `aux_item_schema` etc. once as module-level dicts in `tool_schemas.py`, shared between both tools.

- [ ] **Step 3: Handlers.** Compose existing `StellaModel` methods on the scratch model. No new model-layer code should be needed; if an invariant gap appears (e.g., a method that mutates and can't be cleanly retried), fix it in `xmile.py` with its own test.

- [ ] **Step 4: README.** New "Batch Building" subsection with one complete `build_model` JSON example (the SIR model — same content as the `sir` template, which doubles as documentation of item shapes). Update "Recommended Agent Workflow": `build_model` becomes step 1 for new models; the single-add tools remain for incremental edits.

### Task 4: Simulation via PySD (`stella-mcp[sim]`)

**Files:**
- Create: `stella_mcp/simulate.py`, `tests/test_simulate.py`
- Modify: `pyproject.toml`, `stella_mcp/tool_schemas.py`, `stella_mcp/tool_handlers.py`, `.github/workflows/ci.yml`, `README.md`

**Why PySD and not a hand-rolled integrator:** PySD is the established open-source XMILE runner (this is the upstream-native option); it ships the full builtin function library, delay/smooth state machinery, and graphical-function interpolation that a hand-rolled Euler loop would re-implement worse. Cost: heavy transitive deps (numpy/pandas/xarray) — hence optional extra, never a core dependency.

**Known caveats to surface, not hide:** PySD integrates with Euler only — if the model's `sim_specs.method` is RK4 the tool must include a warning that results will differ from Stella; PySD supports a subset of XMILE, so unsupported constructs must produce a structured error, not a crash.

- [ ] **Step 1: Spike — verify PySD runs the built-in templates (gate for this whole task)**

```bash
uv run --with pysd python - <<'EOF'
import pysd, pathlib
for p in sorted(pathlib.Path("stella_mcp/builtin_templates").glob("*.stmx")):
    m = pysd.read_xmile(str(p))
    df = m.run()
    print(p.name, df.shape, list(df.columns)[:6])
EOF
```

Expected: all 5 templates load and run. The spike must ALSO cover (review finding — templates alone don't prove "files this exporter produces" work):

- A **freshly built model exported through our writer** (not just checked-in templates): build a model via `StellaModel` with display names containing spaces (e.g., `growth rate`), a graphical function, and a module; export with `to_xml()`; run through PySD. The templates already mix display names with spaces against underscore names in equations/connectors — this is exactly where a runner can trip.
- **Parameter naming for overrides:** determine what PySD calls our variables (`m.run(params={...})` key format — PySD typically pythonizes names). Record the mapping rule; the `simulate` tool's `overrides` validation in Step 4 must translate user-facing names (display or underscore form) to PySD's parameter names through that rule, not assume they're identical.

If any spike case fails, STOP and surface the failure before building the tool — the fix may belong in our XMILE export, in the template, or may genuinely bound what `simulate` can support (then document the bound). Record the spike outcome in the commit message body.

Pin the floor to the version the spike ran against. Add a CI leg (single Python version, e.g. 3.12) that installs `--extra dev --extra sim` and runs `tests/test_simulate.py`; the existing matrix legs keep running without `sim`, which also proves the core import path never touches pysd.

- [ ] **Step 3: Write failing tests** in `tests/test_simulate.py`

All pysd-dependent tests guarded with `pytest.importorskip("pysd")`. Cases:
- `simulate` on the loaded `exponential_growth` template returns structured series for the stock; final value > initial (growth); `len(series[i]["points"]) <= max_points`.
- Parameter override (`overrides={"growth_rate": 0}`) → flat trajectory.
- Method warning: model with `method="RK4"` → response includes an `euler_only` warning.
- Without pysd installed (simulate the import failure with `monkeypatch.setitem(sys.modules, "pysd", None)` or similar): structured error `code="sim_dependency_missing"`, message includes `pip install 'stella-mcp[sim]'`.
- `save_results_csv` writes a CSV with a time column.

- [ ] **Step 4: Implement `stella_mcp/simulate.py`**

```python
def run_simulation(
    model: StellaModel,
    overrides: dict[str, float] | None = None,
    max_points: int = 101,
    include: list[str] | None = None,   # default: stocks only
) -> dict[str, Any]: ...
```

Mechanics: lazy `import pysd` inside the function (raise a dedicated `SimulationDependencyError` mapped by `_classify_error` to `sim_dependency_missing`); **export a `copy.deepcopy` of the model, never the session model itself** — `to_xml()` mutates layout state (`_auto_layout`, flow-point recalculation, connector angles, `last_export_warnings`) even with `auto_layout=False`, and a read-style `simulate` call must not silently rewrite the session model's diagram (review finding; see `xmile_io.py` export path). Write to a `tempfile.NamedTemporaryFile(suffix=".stmx")`; `pysd.read_xmile`; `model.run(params=overrides)`; downsample each series to ≤ `max_points` by stride (always keep first and last point); per-series summary `{initial, final, min, max, min_time, max_time}`. `overrides` keys are validated against model variable names *before* running and translated to PySD parameter names via the mapping rule recorded in the Step 1 spike — unknown names are a structured `invalid_input` error listing valid candidates (don't let pysd's KeyError surface raw). Add a test asserting the session model's positions/`last_export_warnings` are unchanged after `simulate`.

Response shape:

```json
{
  "model_id": "...",
  "sim_specs": {...},
  "warnings": ["method is RK4 but simulation uses Euler ..."],
  "series": [{"name": "Population", "points": [{"t": 0, "value": 100.0}, ...],
              "summary": {"initial": 100.0, "final": 245.3, "min": 100.0, "max": 245.3}}]
}
```

- [ ] **Step 5: Schema + handler.** Tool `simulate`: optional `model_id`, `overrides` (object, additionalProperties number), `include` (array of variable names), `max_points` (default 101), `save_results_csv` (filepath). Description must state the extra requirement: "Requires the optional pysd dependency (`pip install 'stella-mcp[sim]'`)".

- [ ] **Step 6: README.** New "Simulation" section: install, one example call, the Euler caveat, the subset-of-XMILE caveat. Update "Recommended Agent Workflow" step list: after validation passes, `simulate` to sanity-check behavior before `save_model`.
